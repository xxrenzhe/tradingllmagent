# VOL 与执行感知的 LLM 交易系统优化方案

> 协调说明：本文晚于 `docs/plan/10.strategy-search-best-practices-optimization-plan.md` 和 `docs/plan/11.nq-historical-data-acquisition-plan.md`。涉及“如何吸收高手经验、如何围绕成交量和执行成本重构策略搜索、如何把回测和前测闭环结合”时，以本文为准。本文不授权任何策略直接实盘交易。

## 1. 结论摘要

高手经验里最有价值的部分是：

- 简单、可量化的基础特征优先于模糊价格行为。
- `VOL` 是日内期货策略的重要核心输入，但必须分层、归一化、过滤噪声。
- OHLCV 回测只描述成交后的结果，不能描述真实 bid/ask、点差扩缩、排队、未成交和滑点。
- 趋势与均值回归是策略结构的两条主线，MA、VOL、MACD、RSI 多数都在描述这两类状态。
- 顺势突破与顺势回踩收复可以作为同一趋势假设下的双入口候选，但必须共享风险预算，不能把两个入口当作独立加仓理由。
- 交易时段必须显式进入归因。Asia、London、New York session 的突破、回踩、成交量和滑点分布不能混在一起评估。
- 回测负责低成本淘汰，paper/sim/live shadow 负责发现真实执行问题。

需要纠正的危险误区是：

- LLM 不能靠一句提示词消除过拟合。
- 挂限价单不能免费解决滑点，只是把主动滑点换成未成交风险和逆向选择风险。
- 直接实盘“撞市场”不是新手优先路线，必须先有严格风险预算、paper shadow 和复盘归因。
- prop-firm 风格的 trailing/EOD drawdown、日内亏损上限、单日交易次数上限和连亏衰减只能作为生存约束，不能证明策略本身有 edge。
- 十年回测不是无意义，但必须按 regime、时间段、成本和样本外验证拆开使用。

因此新的优化路线是：

```text
真实 CME NQ_CME OHLCV
  -> VOL/趋势/均值回归基础特征
  -> 简单策略族组合
  -> 成本压力回测
  -> Quote/盘口执行验证
  -> Paper shadow 复盘
  -> LLM 生成结构化诊断与下一轮假设
  -> 小步参数/规则更新
```

## 2. 核心设计原则

### 2.1 简单优先，但不能粗糙

第一批策略只使用少数可解释基础特征：

- `MA`: 趋势方向、均线斜率、均线间距、价格贴近均线。
- `VOL`: 相对成交量、成交量突增、1m/5m/15m 同步放量。
- `MACD`: 动量确认、动量衰减、零轴附近状态。
- `RSI/z-score`: 均值回归、超买超卖、偏离均线距离。
- `ATR/range`: 波动过滤、自适应止损止盈。

不优先引入复杂模式识别、主观 K 线形态或大量高维特征。新特征必须能说明：

- 计算公式。
- 输入字段。
- 是否可实时获得。
- 是否存在未来函数。
- 预期捕捉趋势还是均值回归。
- 已知失败场景。

### 2.2 VOL 必须分层

不能直接把原始 volume 当作信号。至少拆成以下层级：

- `absolute_volume`: 当前 1m 成交量。
- `relative_volume`: 当前 volume / 同 session 过去 N 分钟均值。
- `volume_percentile`: 当前 volume 在过去 N 天同一分钟的分位数。
- `multi_timeframe_volume`: 1m、5m、15m 是否同时放大。
- `volume_price_confirm`: 放量时 close 是否突破区间或沿趋势推进。
- `volume_absorption`: 放量但价格不动，作为趋势失败或反转候选。
- `low_volume_filter`: 低成交量时禁止开仓。

第一轮 VOL 策略只允许进入以下三类：

- 放量突破。
- 放量趋势延续。
- 放量但价格不跟随后的均值回归。

### 2.3 执行成本是一等约束

OHLCV 回测只回答“信号是否可能有 gross edge”。进入候选前必须加入：

- 固定保守成本。
- 额外 1-2 tick 滑点压力测试。
- 只在流动性足够时允许交易。
- 开盘、新闻、低流动性时段的单独归因。

Quote 或盘口验证阶段必须补充：

- bid/ask spread 分布。
- market order 成本。
- limit order 未成交率。
- limit order 成交后的逆向选择。
- 信号触发到下单之间的延迟敏感性。

### 2.4 LLM 是研究助理，不是统计豁免

LLM 的职责是：

- 生成可检验假设。
- 总结失败原因。
- 归纳 regime 和特征表现。
- 提出下一轮参数范围。
- 审查是否存在过拟合、泄漏或执行不可行。

LLM 不允许：

- 读取 final holdout 后继续改策略。
- 用自然语言结论覆盖硬性风控。
- 因为“报告看起来合理”而放宽成本和样本外门槛。
- 直接输出实盘指令。

## 3. 数据与字段规范

### 3.1 当前可用数据

`NQ_CME` 已由 Databento `GLBX.MDP3` `ohlcv-1m` 转换生成：

- 路径：`data/bars/1m/NQ_CME/`
- 时间范围：`2010-06-06 22:00:00` 到 `2026-04-27 23:59:00` UTC。
- 行数：约 `5,378,727`。
- 分区数：`4930`。
- 原始 Databento `volume` 已映射到 `tick_count`、`bid_size_sum`、`ask_size_sum`。
- OHLCV 数据没有真实 spread，因此 `avg_spread` 为空。

策略侧应把 `tick_count` 视作 1m 成交量。命名上后续应补一个语义别名：

```text
bar_volume = tick_count
```

避免误以为 `tick_count` 是逐笔 tick 数。

### 3.2 必须补充的数据

OHLCV 不能完成真实执行验证。候选策略晋级后必须下载 Databento：

- `TBBO`: 先验证 top-of-book bid/ask spread 和 market order 成本。
- `MBP-1`: 如果候选依赖 limit order，再验证 top level size、成交概率和逆向选择。

Quote/盘口数据不要求先全量多年下载。优先下载：

- 候选策略交易最密集的月份。
- 高波动月份。
- 普通波动月份。
- 开盘和收盘前交易最多的窗口。
- 重大宏观事件附近窗口。

## 4. 策略搜索分层

### 4.1 第一层：OHLCV 快速筛选

目标是找出可能有 gross edge 的简单策略，不追求立即实盘。

硬性门槛：

- 年交易次数 `>= 300` 作为早期发现门槛。
- gross PnL > 0。
- 平均每笔 gross PnL 至少覆盖 `2x` 当前保守 round-trip cost。
- 加 1 tick 额外滑点后仍不明显崩溃。
- 至少 3 个非重叠验证窗口有交易。
- 参数邻域表现不脆弱。

强候选门槛：

- 年交易次数 `>= 1000`。
- net Sharpe `>= 1`。
- win probability `>= 53%` 或 profit factor `>= 1.2`。
- walk-forward 多窗口稳定。
- final holdout 不显著衰减。

最终目标仍保持：

- 年交易次数 `> 1000`。
- Sharpe `> 2`。
- 盈利概率 `> 53%`。
- 成本、滑点、quote replay、paper shadow 全部通过。

### 4.2 第二层：Quote 执行验证

候选策略进入 quote 验证后，必须生成以下报告：

- 原始 bar 回测收益。
- market order 按 bid/ask 成本重放收益。
- limit order fill 率。
- missed fill 后的机会成本。
- 成交后 1/3/5/15 分钟不利移动统计。
- spread 分位数和成本压力分布。

晋级条件：

- market order 模式不能把收益完全吃掉。
- limit order 模式不能靠极低 fill rate 虚高收益。
- 成交后的逆向选择不能显著恶化。
- 高 spread 时段过滤后，收益质量改善或至少不恶化。

### 4.3 第三层：Paper Shadow 复盘

Paper shadow 不是直接实盘，而是把策略挂在实时市场旁边收集：

- 应该下单的信号。
- 当时 bid/ask。
- 如果 market order 成本是多少。
- 如果 limit order 是否会成交。
- 未成交后价格如何走。
- 实际 spread、延迟、跳价、滑点。
- LLM 对每笔交易的事后归因。

输出是结构化复盘，不是自由聊天：

```json
{
  "signal_id": "...",
  "expected_edge": 12.5,
  "actual_fill_mode": "missed_limit",
  "spread_ticks": 1,
  "adverse_selection_ticks_5m": 3,
  "regime": "high_vol_breakout",
  "llm_diagnosis": "...",
  "allowed_mutations": ["raise_volume_threshold", "avoid_first_5m"],
  "blocked_mutations": ["read_final_holdout", "remove_costs"]
}
```

## 5. 第一批策略族

### 5.1 VOL 放量突破

核心假设：

- 价格突破最近区间时，如果 1m 和 5m volume 同步放大，趋势延续概率更高。
- 该策略可与 `ma_pullback_volume_confirm` 共享同一趋势假设，用于测试“突破先手”和“回踩确认”两类入口的相对质量。

入场条件示例：

- close 突破过去 N 分钟 high。
- `volume / volume_ma >= threshold`。
- 5m volume percentile 高于过去 M 天同时间分位。
- MA slope 同向。
- spread 或成本代理不过高。

失败模式：

- 新闻尖峰后反转。
- 开盘假突破。
- 放量但价格被吸收。
- 突破入口与后续回踩入口重复暴露同一方向风险。

### 5.2 MA 趋势回踩 + VOL 确认

核心假设：

- 主趋势明确时，价格回踩 MA 后恢复，并伴随 volume 回升，延续概率更高。
- 回踩收复入口不是突破亏损后的自动补救单，必须重新满足趋势、成交量和成本条件。

入场条件示例：

- fast MA > slow MA。
- slow MA slope > 0。
- price 回踩 fast/slow MA 附近。
- 回到 fast MA 上方时 volume 放大。
- 如果同一趋势假设下已有突破入口信号，回踩入口必须继承该假设的剩余风险预算。

失败模式：

- 震荡区间反复穿 MA。
- 趋势末端回踩变反转。
- 在同一 session 内连续尝试同方向回踩导致相关亏损累积。

### 5.3 VOL 吸收后的均值回归

核心假设：

- volume 放大但价格无法继续推进，说明突破失败或吸收，短线回归概率提高。

入场条件示例：

- volume spike。
- high/low 突破失败。
- close 回到区间内。
- price distance from MA 过大。

失败模式：

- 真趋势启动初期被误判为吸收。
- 高波动新闻日连续扫损。

### 5.4 MACD/MA 动量确认

核心假设：

- MACD 只作为趋势确认，不单独作为入场。

使用方式：

- MACD histogram 与 MA slope 同向。
- histogram 从负转正只在高 volume regime 下有效。
- histogram 衰减作为退出或减仓信号。

### 5.5 RSI/z-score 均值回归

核心假设：

- 低趋势、低 volume 方向性时，价格偏离均线过远更容易回归。

使用限制：

- 禁止在高 volume breakout regime 里逆势做均值回归。
- 必须有 ATR 自适应止损。
- 必须限制开盘前几分钟和重大事件窗口。

## 6. 过拟合控制

### 6.1 搜索日志不可丢

所有失败策略也必须记录：

- 策略 family。
- 特征组合。
- 参数。
- 数据窗口。
- 成本模型。
- 失败原因。
- 是否反向更好。

否则系统只记住成功候选，会制造幸存者偏差。

### 6.2 数据切分

最低要求：

- discovery。
- validation。
- test。
- final holdout。
- paper shadow。

规则：

- LLM 可以看 discovery 和 validation 报告。
- LLM 可以看 test 的聚合分数，但不能用 test 反复改参数。
- final holdout 只在晋级时读取一次。
- 读取 final holdout 后，如果继续改策略，必须生成新版本并重新隔离新的 final holdout。

### 6.3 参数稳定性

策略晋级前必须做：

- 参数邻域热力图。
- threshold 上下浮动。
- stop/take-profit 上下浮动。
- 不同年份和波动 regime 分组。
- 交易时段分组。

如果只有单一点参数盈利，默认视为过拟合。

## 7. LLM 复盘与优化流程

### 7.1 LLM 输入

LLM 不直接读全量 K 线，而读结构化报告：

- 策略定义。
- 特征快照。
- 回测统计。
- 交易分布。
- regime 分组。
- 成本压力结果。
- quote replay 结果。
- paper shadow 结果。

### 7.2 LLM 输出

每轮只能输出以下类型变更：

- 调整一个阈值范围。
- 增加或移除一个过滤条件。
- 调整一个时段限制。
- 调整一个退出规则。
- 标记策略放弃。

每个建议必须包含：

- 依据。
- 预期改善指标。
- 可能副作用。
- 验证窗口。
- 禁止读取的数据。

### 7.3 禁止行为

- 一次改很多参数。
- 回看 final holdout 后继续调参。
- 因为单次 paper 结果好就扩大仓位。
- 因为胜率高就忽略盈亏比和尾部亏损。
- 因为 LLM 给出自信解释就跳过统计验证。

## 8. 实施任务拆解

### 8.1 数据语义修正

- 在 bar schema 或 feature 层增加 `bar_volume = tick_count` 语义别名。
- 对 Databento OHLCV 导入报告增加 `volume_field_mapping`。
- 在文档和 UI 中避免把 `tick_count` 误称为真实 tick 数。

验收标准：

- 策略特征可以通过 `bar_volume` 访问 NQ_CME 1m volume。
- 报告中清楚说明 OHLCV 无 bid/ask spread。

### 8.2 VOL 特征落地

新增或确认以下可执行特征：

- `volume_ma_5`
- `volume_ma_20`
- `relative_volume_5`
- `relative_volume_20`
- `volume_percentile_session`
- `volume_spike_flag`
- `multi_timeframe_volume_confirm`
- `volume_price_confirm`
- `volume_absorption_flag`
- `low_volume_filter`

验收标准：

- 所有特征进入 feature registry。
- 每个特征有实现、warmup、lookback、泄漏风险说明。
- 每笔交易能导出触发时的关键 VOL 特征值。

### 8.3 简单策略族生成

新增第一批策略模板：

- `vol_breakout_trend`
- `ma_pullback_volume_confirm`
- `volume_absorption_reversion`
- `macd_ma_volume_confirm`
- `rsi_reversion_low_volume`

验收标准：

- 每个策略只有 3-6 个核心条件。
- 每个策略能明确归类为趋势或均值回归。
- 每个策略有反向版本或失败反向测试。

### 8.4 成本与限价单模型

新增执行模型：

- market order baseline。
- fixed conservative cost。
- limit order optimistic。
- limit order with missed fills。
- limit order adverse selection stress。

验收标准：

- 同一个候选可以输出不同执行假设下的收益。
- limit order 不成交时不允许默认按理想价格成交。
- 报告包含 fill rate 和 missed opportunity。

### 8.5 Paper Shadow 复盘

新增 paper shadow 数据结构：

- signal intent。
- entry_variant: `breakout` 或 `pullback_reclaim`。
- shared_hypothesis_id: 同一趋势假设下多个入口共享的风险归因 ID。
- session_bucket: `asia_2000_0000_ny`、`london_0200_0500_ny`、`new_york_0800_1100_ny` 或 `other`。
- simulated market fill。
- simulated limit fill。
- missed fill result。
- post-signal excursion。
- risk_budget_snapshot: 单笔风险、日内剩余亏损额度、trailing/EOD drawdown 剩余额度。
- LLM diagnosis。
- next mutation proposal。

验收标准：

- 可以连续记录至少 3 个交易日。
- LLM 只读取 paper shadow 报告，不直接发单。
- 同一 `shared_hypothesis_id` 下的突破和回踩入口必须能合并统计总风险与总收益。
- 每轮调整有审计日志。

### 8.6 宏观事件与时段过滤补强

`docs/plan/2.macro-event-aware-nq-strategy-optimization.md` 已规定 CPI、PPI、NFP、FOMC、Fed 讲话、GDP、PCE 等事件上下文。VOL 策略必须继承该约束，因为高 VOL 很可能来自事件冲击，而事件冲击下的 spread、滑点和假突破分布完全不同。

新增约束：

- 所有 VOL 策略必须输出 `session_policy`，至少拆分 Asia `20:00-00:00`、London `02:00-05:00`、New York `08:00-11:00` 和其他时段，时间基准为纽约时间。
- 所有 VOL 策略必须输出 `event_window_policy`。
- 默认禁止在高影响事件发布前后窗口开新仓，除非策略显式归类为 event strategy。
- 回测报告必须拆分 `session_bucket` 表现，不能用全日聚合收益掩盖某个 session 的负期望。
- 回测报告必须拆分 `event_window` 与 `non_event_window` 表现。
- LLM 复盘可以读取事件归因摘要，但不能把 event-window 盈利直接推广到普通交易日。

验收标准：

- `volume_spike_flag` 必须能标记事件窗口内外的表现差异。
- leaderboard 展示 session Sharpe、non-event Sharpe、event dependency ratio 和 event-window drawdown。
- 如果策略只在单一 session 有效，strategy card 必须记录该 session 依赖，不能推广到其他时段。
- 如果策略收益主要来自少数事件窗口，默认不能进入 paper shadow。

### 8.7 触发式 LLM 与 token 成本控制

`docs/plan/8.llm-trigger-gate-optimization-plan.md` 已规定触发式 LLM 门控。VOL 方案不能把 LLM 放到每根 1m K 线上。

执行原则：

- 1m bar 用于特征计算和 deterministic pre-gate。
- LLM 只在候选策略完成一轮回测、quote replay 或 paper shadow 汇总后运行。
- 运行期只允许在 5m/15m bar close、关键位触达、异常 spread/slippage、paper shadow drift 超限时触发 LLM review。
- 每个策略每天最多触发固定次数 LLM 深度复盘，超出后只写入待审队列。

验收标准：

- 每次 LLM 调用都有 `trigger_reason`、`input_artifact_hash`、`token_estimate`、`allowed_actions`。
- LLM 输出只能是小步 mutation 或放弃建议，不能是直接下单命令。
- token 成本必须进入实验报告。

### 8.8 Strategy Card 与模块记忆回写

`docs/plan/5.agent-driven-trading-system-optimization.md` 要求交易经验沉淀为 strategy card、module library 和 performance memory。VOL 策略搜索的输出必须直接进入这些资产，而不是只生成一次性 leaderboard。

新增资产：

- `vol_feature_card`: 每个 VOL 特征的定义、有效场景、失败场景。
- `vol_strategy_card`: 每个候选策略的 family、假设、参数稳定区间、成本敏感性、事件依赖。
- `execution_card`: quote replay 和 paper shadow 得出的 spread、fill、missed fill、adverse selection 统计。
- `mutation_memory`: LLM 建议过的参数调整、是否有效、在哪个窗口失效。

验收标准：

- 每个晋级候选必须有 strategy card。
- 每个失败候选也必须有 rejection reason。
- 同一 family 的重复失败会降低下一轮生成权重。

### 8.9 WebUI 与报告落地

现有 WebUI 已有策略列表和历史表现展示需求。VOL 方案需要新增可检查视图：

- VOL feature readiness。
- VOL strategy family leaderboard。
- 成本压力对比图。
- quote replay 执行归因。
- paper shadow drift 视图。
- event-window vs non-event 表现拆分。
- 参数稳定性热力图。

验收标准：

- 用户可以按 family、VOL 阈值、交易时段、event dependency、成本压力结果筛选策略。
- 可以选择多个策略，对比净值曲线、回撤、交易频次、win rate、profit factor 和成本后 Sharpe。
- 每个策略详情页必须显示为什么能或不能进入下一阶段。

### 8.11 BD 落地拆解

后续实施时应拆成一个 epic 和以下小任务：

1. `Expose bar_volume semantics for NQ_CME`: 实现 `bar_volume = tick_count` 语义别名和报告字段。
2. `Implement VOL feature layer`: 实现 relative volume、volume percentile、multi-timeframe confirm、absorption 等特征。
3. `Add VOL seed strategy families`: 生成 5 个简单策略族模板和参数空间。
4. `Run NQ_CME VOL pre-screen`: 用 2010-2026 数据跑 gross-edge 初筛。
5. `Add event-aware VOL attribution`: 拆分 event/non-event 表现。
6. `Add execution cost stress models`: 增加 market、fixed conservative、limit missed-fill、adverse-selection 压力模型。
7. `Add quote replay for VOL candidates`: 对通过初筛的候选导入 TBBO/MBP-1 并回放。
8. `Add VOL paper shadow review artifact`: 记录实时观察、未成交和 LLM 小步 mutation。
9. `Add VOL LLM trigger audit artifact`: 记录 LLM review 触发原因、输入 hash、token 估算、允许动作和 mutation outcome。
10. `Expose VOL reports in WebUI`: 支持筛选、对比和策略详情。
11. `Backfill VOL mutation memory`: 将成功和失败 mutation 写回长期记忆。

每完成一个小任务必须关闭对应 bd，并按当前用户要求提交本地 git commit，不做 git push。

## 9. 阶段计划

### Phase 1: VOL 基础特征与语义修正

目标：

- 修正 `tick_count` 语义。
- 实现基础 VOL 特征。
- 在 `NQ_CME` 上跑 feature readiness。

完成标准：

- VOL 特征可被策略 grammar 调用。
- 单元测试覆盖 volume 映射。
- 输出 `vol_feature_readiness.json`。

### Phase 2: 简单策略族搜索

目标：

- 只用 MA/VOL/MACD/RSI/ATR 五类基础特征。
- 先找 gross edge，不追求立刻 Sharpe > 2。

完成标准：

- 至少生成 50 个简单策略候选。
- 每个候选有趋势/均值回归标签。
- 输出 family-level 归因。
- 输出 `vol_strategy_leaderboard.json`。

### Phase 3: 执行压力验证

目标：

- 对候选加固定成本、额外滑点、低流动性过滤。
- 下载少量 Databento TBBO/MBP-1 做 quote replay。

完成标准：

- 候选必须通过 market/limit 两类执行报告。
- 不通过则进入失败记忆。
- 输出 `vol_cost_stress_report.json` 和 `vol_quote_replay_report.json`。

### Phase 4: Paper Shadow

目标：

- 将候选挂到实时数据旁边观察，不实盘。
- 收集真实 spread、未成交、错过机会和逆向选择。

完成标准：

- 至少 3 个交易日 paper shadow 报告。
- LLM 输出下一轮小步变更。
- 输出 `vol_paper_shadow_review.json`。

### Phase 5: 小仓位前测门槛

目标：

- 只在 paper shadow 稳定后评估是否进入 sim 或 micro-live。
- 使用 prop-firm 风格风控作为生存边界，而不是收益目标。

完成标准：

- 明确风控白名单。
- 明确最大日亏损、最大单笔亏损、最大连续亏损。
- 明确 trailing/EOD drawdown 计算口径、单日交易次数上限、连亏后的风险衰减规则。
- 同一趋势假设下的突破与回踩入口共享单日风险预算，亏损后不能自动重试。
- 默认不隔夜保留研究意义上的风险敞口，除非后续 overnight 风控方案单独批准。
- 默认仍不自动实盘，除非后续 live 方案单独批准。

## 10. 立即执行建议

当前最务实的下一步不是继续随机组合复杂特征，而是：

1. 把 `NQ_CME` 的 `tick_count` 统一暴露为 `bar_volume`。
2. 实现 VOL 分层特征。
3. 生成 5 个简单策略族的种子策略。
4. 在 `NQ_CME` 2010-2026 数据上跑低成本筛选。
5. 对通过 gross edge 的候选再下载 quote 数据做执行验证。
6. 对最好的候选补 event/non-event 拆分和 paper shadow 计划。

如果第一批 VOL/MA 策略仍完全没有 gross edge，应先复盘：

- 是否选错交易时段。
- 是否 volume 阈值过低，噪声太多。
- 是否开盘/新闻冲击没有隔离。
- 是否止损止盈不适配 NQ 波动。
- 是否策略方向应反向。

只有当 gross edge 出现后，才值得继续投入更高成本的实时 LLM 复盘和 quote/盘口数据。
