# NQ 历史数据获取与验证优化方案

> 协调说明：本文晚于 `docs/plan/10.strategy-search-best-practices-optimization-plan.md`。涉及 NQ 历史数据来源、数据采购顺序、免费/付费数据边界、策略搜索与真实执行成本验证的数据分层时，以本文为准。本文不授权任何策略直接实盘交易。

## 1. 结论摘要

当前最佳数据方案不是单一来源，而是两层数据管线：

```text
多年 1m K线低成本策略挖掘
  -> 候选策略初筛
  -> 少量真实 CME 盘口数据验证
  -> 真实 spread/slippage 成本归因
  -> 再决定是否进入 paper shadow
```

推荐组合：

- 第一层：使用 FirstRate Data 的 NQ 1-minute historical intraday bars，作为大规模策略搜索、特征组合、LLM 回测和 walk-forward 验证的主数据源。
- 第二层：使用 Databento CME Globex `GLBX.MDP3` 的 `TBBO` 或 `MBP-1`，只对通过初筛的候选策略做真实执行成本验证。
- 辅助层：使用 Yahoo `NQ=F`、`QQQ`、`NDX` 等免费代理数据做 smoke test、数据管线调试或非常早期的方向性粗筛，但不得作为最终盈利结论依据。

核心判断：

- 现在不是直接购买多年 tick/order book 的阶段；策略尚未证明 gross edge，直接买高精度全量数据会放大成本。
- 现在也不能继续依赖 CFD 或指数代理数据做最终结论；已有诊断显示，执行成本和 bid/ask 建模是策略质量判断的关键瓶颈。
- 先用低成本多年 1m bars 扩大搜索窗口，再用真实 CME 盘口验证少量候选，是当前性价比最高且工程上可落地的路径。

## 2. 数据源分层

### 2.1 策略挖掘主数据源：FirstRate Data NQ 1m

用途：

- 多年 NQ 1m OHLCV 回测。
- LLM 生成策略后的批量评估。
- 特征挖掘、策略 grammar 搜索、参数稳定性检查。
- walk-forward、regime split、day-of-week、time-of-day、volatility bucket 分析。

优势：

- 成本低于全量 tick、BBO 或 order book 数据。
- 可本地下载，适合接入现有 `data build-bars`、backtest、leaderboard、strategy search pipeline。
- 覆盖多年历史，更适合分析 regime 稳定性，而不是只在一两个月窗口里寻找偶然结果。

限制：

- 缺少真实 bid/ask。
- 无法直接判断盘口深度、spread、真实成交可行性。
- 连续合约的换月规则必须明确记录，避免把 rollover gap 当作交易信号。

使用边界：

- 可以用于发现候选策略。
- 可以用于计算保守 bar-level cost model 下的初筛结果。
- 不得单独用于宣布策略可实盘盈利。

### 2.2 最终验证数据源：Databento CME Globex

用途：

- 对候选策略做真实 NQ futures 执行成本验证。
- 使用 `TBBO` 或 `MBP-1` 检查 spread、bid/ask fill、滑点敏感性、成交时间可行性。
- 校准 1m bar 回测中的 conservative cost model。

推荐 schema：

- `TBBO`：适合先验证 top-of-book bid/ask 成本，数据量和成本通常低于深度盘口。
- `MBP-1`：适合需要 top level size、book update 和更细执行模拟的候选。
- 暂不建议首轮使用深层 order book 或多年 tick 全量搜索。

使用边界：

- 只对已通过 FirstRate 多年 1m 初筛的候选策略购买和下载。
- 验证窗口应覆盖不同 regime，包括高波动日、普通日、开盘、午盘和收盘前。
- 验证结果必须回写 strategy card、leaderboard、cost attribution report。

### 2.3 免费辅助数据源：Yahoo / ETF / Index

用途：

- 数据管线 smoke test。
- UI、报表、策略列表和图表功能调试。
- 非正式方向性对照，例如 `NQ=F`、`QQQ`、`NDX`。

限制：

- 连续合约规则不透明。
- 分钟历史覆盖有限。
- 没有真实 bid/ask。
- 不能替代 CME NQ futures 数据。

使用边界：

- 只能作为开发和粗筛辅助。
- 不能作为 Sharpe、胜率、年交易次数目标达成的最终证据。

### 2.4 不作为主路径的数据源

- Twelve Data：文档和 API 确实存在部分 commodity futures，但未确认可获取 CME NQ/MNQ futures；免费层也不等价于可免费获取完整 commodity futures 历史。可作为代理资产辅助源，不作为 NQ 主数据源。
- CME DataMine：官方质量高，但采购流程和成本更偏机构级，当前阶段不优先。
- AlgoSeek 直购：质量较高，但通常比 FirstRate bar 数据更贵，适合后续预算提高后评估。
- QuantConnect：平台内研究方便，但不适合作为当前本地 pipeline 的原始数据下载主路径。

## 3. 目标数据合同

### 3.1 Symbol 定义

新增或保留两个逻辑 symbol：

- `NQ_1M`: FirstRate Data 连续合约 1m bars，用于策略搜索。
- `NQ_CME`: Databento CME Globex 真实 futures 数据，用于候选验证。

建议字段：

```yaml
NQ_1M:
  asset_class: futures
  venue: CME
  contract: NQ
  source: firstratedata
  bar_timeframe: 1m
  tick_size: 0.25
  point_value: 20
  tick_value: 5
  execution_grade: research

NQ_CME:
  asset_class: futures
  venue: CME
  contract: NQ
  source: databento
  dataset: GLBX.MDP3
  preferred_schema: TBBO
  tick_size: 0.25
  point_value: 20
  tick_value: 5
  execution_grade: validation
```

### 3.2 Bar 数据规范

FirstRate Data 接入后，应标准化为现有 bar schema：

- `timestamp`
- `open`
- `high`
- `low`
- `close`
- `volume`
- `symbol`
- `source`
- `contract_mode`
- `roll_rule`
- `ingested_at`

必须记录：

- 数据源版本或下载日期。
- 时区。
- 是否 RTH/ETH。
- 连续合约换月规则。
- 是否包含成交量。
- 是否存在缺口和重复时间戳。

### 3.3 盘口数据规范

Databento 接入后，应标准化为现有 tick 或 quote schema：

- `timestamp`
- `bid`
- `ask`
- `bid_size`
- `ask_size`
- `symbol`
- `source`
- `schema`
- `raw_symbol`

必须支持：

- bid/ask spread 分布统计。
- strategy entry/exit timestamp 对齐。
- bar signal 到 quote fill 的延迟模拟。
- conservative、baseline、optimistic 三档成本场景。

## 4. 数据获取实施阶段

### 4.1 阶段一：FirstRate Data 1m bars 接入

目标：

- 将下载得到的 NQ 1m CSV 文件导入本地标准 bar 数据目录。
- 支持按日期范围构建研究窗口。
- 保留 source metadata 和 roll metadata。

任务：

- 增加 FirstRate CSV loader。
- 增加 `NQ_1M` symbol config。
- 增加数据质量检查：缺失分钟、重复分钟、异常 OHLC、异常 volume、roll gap。
- 增加导入报告：日期范围、bar 数、缺失率、交易时段覆盖、价格跳变 top events。
- 让 strategy search 支持显式选择 `NQ_1M`。

验收标准：

- 能导入至少一年 NQ 1m 数据。
- 能运行现有 backtest 和 leaderboard。
- 数据质量报告能指出缺口、重复和异常价格。
- 同一输入文件重复导入结果可复现。

### 4.2 阶段二：多年搜索窗口重构

目标：

- 用多年数据替代当前短窗口策略搜索。
- 把 discovery、validation、final holdout 分开。

推荐窗口：

- discovery：多个非连续月份，覆盖趋势、震荡、高波动、低波动。
- validation：至少 2-3 年，按季度或月度 walk-forward。
- final holdout：完全隐藏，LLM 不可读取，不参与策略生成反馈。

任务：

- 增加 dataset split manifest。
- 为每轮搜索固化数据版本 hash。
- leaderboard 增加 source、window、roll rule、cost model 字段。
- 强制报告 gross edge、net edge、turnover、daily concentration、regime stability。

验收标准：

- 每个策略结果都能追溯到数据版本和窗口定义。
- LLM 反馈不能读取 final holdout 明细。
- 同一策略在不同窗口的退化能被明确展示。

### 4.3 阶段三：Databento 候选验证

目标：

- 对少量候选策略下载真实 CME `TBBO` 或 `MBP-1` 数据。
- 验证 bar-level 回测是否高估收益。

触发条件：

- FirstRate 多年 1m 回测中，pre-cost gross edge 为正。
- net-of-cost Sharpe 至少大于 0.5。
- 年交易次数满足目标区间。
- 胜率、profit factor 或 average trade 至少有一个显示正向边际。
- 不依赖单一天或单一 regime 获利。

任务：

- 增加 Databento quote downloader。
- 增加 quote-level replay。
- 将 bar signal 映射到最近可交易 bid/ask。
- 计算真实 spread cost、slippage sensitivity、latency sensitivity。
- 生成 candidate execution validation report。

验收标准：

- 每个候选策略都有 quote-level replay 报告。
- 报告包含 spread 分布、平均执行成本、最差分位执行成本、成交失败率。
- 若真实 bid/ask 验证后 edge 消失，策略必须降级或淘汰。

## 5. 成本控制策略

### 5.1 下载成本控制

- FirstRate Data 一次性或低成本购买多年 1m bars，作为主要搜索材料。
- Databento 只下载候选策略对应的验证窗口，不做全量多年盘口搜索。
- 优先下载 `TBBO`，只有策略需要 size 或更细盘口时再下载 `MBP-1`。
- 每次 Databento 下载前预估日期范围、schema、symbol 和预算。

### 5.2 计算成本控制

- 先用 1m bars 进行便宜 pre-screen。
- 只对通过 pre-screen 的策略运行完整 walk-forward。
- 只对通过 walk-forward 的策略运行 quote-level replay。
- LLM 只读取摘要、失败原因和归因报告，不读取全量 bar 或 quote 数据。

### 5.3 过拟合成本控制

- 每轮搜索记录试验次数。
- 使用隐藏 final holdout。
- 对高 Sharpe 策略要求跨窗口稳定。
- 对低交易成本敏感策略要求额外 1 tick 滑点压力测试。

## 6. 进入策略搜索的最低数据门槛

在继续大规模搜索前，至少满足：

- 有 2 年以上 NQ 1m bars。
- 已完成缺失和异常数据报告。
- 已明确 RTH/ETH 时段定义。
- 已明确连续合约 roll rule。
- 已有保守 round-trip cost model。
- 已能按 discovery/validation/final holdout 分割。

在宣布候选策略满足目标前，至少满足：

- 年交易次数 `> 1000`。
- net Sharpe `> 2`。
- win probability `> 53%`。
- profit factor `> 1.2`。
- 多窗口不崩溃。
- Databento quote-level replay 后仍为正。
- 额外 1 tick 滑点压力测试后仍不崩溃。

## 7. 当前落地优先级

1. 获取 FirstRate Data NQ 1m 历史数据。
2. 实现 FirstRate CSV loader 和 `NQ_1M` 配置。
3. 生成数据质量报告和 split manifest。
4. 用 `NQ_1M` 重跑策略搜索，但先降低目标寻找弱正 edge。
5. 把通过初筛的候选策略提交 Databento `TBBO` 验证。
6. 用真实 spread 结果校准成本模型。
7. 只有通过 quote-level replay 的策略才允许进入 paper shadow。

## 8. 风险与防线

- 数据代理风险：`NQ=F`、`QQQ`、`NDX` 与 CME NQ futures 不等价，不能混作最终证据。
- 换月风险：连续合约 roll gap 可能制造伪信号，必须在报告中标注。
- 成本低估风险：1m OHLCV 无 bid/ask，必须用 Databento 校准。
- 过拟合风险：多年搜索会增加 data snooping，必须保留隐藏 holdout。
- 预算风险：真实盘口数据只用于候选验证，不用于全量策略暴力搜索。
