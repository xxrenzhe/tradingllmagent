# 交易策略搜索最佳实践调研与优化落地方案

> 协调说明：本文基于第一轮策略搜索结果复盘生成，晚于 `docs/plan/9.llm-trading-optimization-factory.md`。涉及“为什么没有找到盈利策略、下一轮如何重构特征与策略生成、如何防止过拟合和伪发现”时，以本文为准。本文不授权任何策略直接实盘交易。

## 1. 结论摘要

第一轮没有找到可盈利策略，主要不是因为 Sharpe 门槛太高，而是当前搜索空间没有形成正边际：

- 257 条首轮结果中，测试 Sharpe `> 0` 的策略数量为 0。
- 年交易次数 `> 1000` 的候选有 72 条，但全部测试净收益为负。
- 把每笔约 15 美元回合成本加回去后，活跃候选仍没有正的测试端 gross edge。
- 随机组合出的 `feature_set` 目前主要是策略元数据，回测执行层仍按固定 family 逻辑运行，很多被挖掘特征没有真正成为入场、过滤或退出条件。
- 多数 seed strategy 是裸动量、EMA 回踩、z-score 均值回归、前高前低突破、固定止损止盈；这些形态在 NQ 1m 上容易被噪声、价差和 regime 切换击穿。

因此，下一阶段的重点不是继续扩大 trial 数，而是重构搜索系统：

```text
Feature Registry
  -> Executable Feature Engine
  -> Signal Grammar
  -> Strategy Mutations
  -> Cheap Pre-Screen
  -> Walk-Forward Validation
  -> Anti-Overfit Promotion
  -> Paper Shadow Attribution
  -> Memory-Guided Next Search
```

## 2. 联网调研要点

本次调研参考了量化交易和金融机器学习中反复出现的实践共识：

- 样本外验证、walk-forward、交易成本和滑点必须作为策略开发的一等约束，而不是回测完成后的修饰项。
- 金融时间序列存在强自相关和标签重叠，普通随机交叉验证会泄漏信息；需要 purging、embargo、非重叠测试窗口或等价隔离机制。
- 大量搜索策略时，最严重的问题是 data snooping 和 backtest overfitting；必须使用多重检验、PBO、Deflated Sharpe、最终隐藏样本等约束。
- 短周期策略需要把 bid/ask、spread、成交假设、延迟和容量纳入回测；只看 mid-price 或 bar close 容易高估策略。
- 特征挖掘必须落到可执行条件，并且记录数据可得性、泄漏风险、lookback、warmup、适用时段和真实执行约束。

参考资料：

- López de Prado, *Advances in Financial Machine Learning*: purged k-fold、embargo、金融标签泄漏控制。
- Bailey, Borwein, López de Prado, Zhu, *The Probability of Backtest Overfitting*: https://ssrn.com/abstract=2326253
- Bailey and López de Prado, *The Deflated Sharpe Ratio*: https://ssrn.com/abstract=2460551
- White, *A Reality Check for Data Snooping*: 多策略试验中的 data snooping 问题。
- QuantStart, *Successful Backtesting of Algorithmic Trading Strategies - Part I*: https://www.quantstart.com/articles/Successful-Backtesting-of-Algorithmic-Trading-Strategies-Part-I/
- QuantStart, *Successful Backtesting of Algorithmic Trading Strategies - Part II*: https://www.quantstart.com/articles/Successful-Backtesting-of-Algorithmic-Trading-Strategies-Part-II/

## 3. 第一轮失败原因分解

### 3.1 特征没有充分进入执行逻辑

当前 `strategies/nq_generated_feature_combo_*.yaml` 包含 `feature_set`，但回测层实际逻辑在 `src/tlm/backtest.py` 中按 `strategy_family` 路由：

- `intraday_momentum`: 主要执行 close 动量阈值。
- `trend_pullback`: 主要执行 EMA fast/slow 回踩。
- `regime_filtered_mean_reversion`: 主要执行 close z-score。
- `volatility_expansion`: 主要执行当根 range expansion + prior high/low。
- `time_of_day_edge`: 主要执行固定时间方向。
- `gap_fade_or_continuation`: 主要执行开盘 gap fade/continuation。

这意味着很多特征只影响“候选说明”，没有实际改变交易条件。LLM 或随机组合生成了看似丰富的 feature mix，但真实回测仍在测试少数硬编码信号。

### 3.2 策略 grammar 表达力不足

当前策略多数只有：

- 单一入场触发。
- 固定 stop/take-profit。
- 固定 max holding。
- 简单 session window。
- 简单 daily trade cap。

缺少真正影响 intraday edge 的结构：

- regime filter: 趋势日、震荡日、高波动日、低流动性日。
- time-of-day condition: 开盘 30 分钟、午盘、收盘前，不同时段不同策略。
- volatility-scaled exit: ATR/realized-volatility 自适应止损止盈。
- spread/liquidity gate: spread 过宽、tick count 过低时禁止交易。
- event gate: 宏观事件前后不同处理。
- inverse mutation: 系统性亏损信号自动反向验证。
- exit-only optimization: 入场可保留，优先改退出和过滤。

### 3.3 搜索目标过晚才反馈

现在很多候选需要完整 rolling validation 后才知道明显不行。对于高频短周期策略，应先用便宜的 pre-screen 拦截：

- pre-cost gross edge 是否为正。
- 平均每笔毛收益是否能覆盖至少 2-3 倍成本。
- 每日收益是否过度集中。
- 胜率、盈亏比、持仓时间是否符合策略假设。
- 同一信号反向后是否明显更好。

如果 pre-screen 已经显示 gross edge 为负，则无需进入昂贵的完整验证。

### 3.4 第一轮窗口短且 regime 单一

2018-05-24 到 2018-07-26 窗口适合作为首轮验证，但不足以发现稳定策略：

- 只覆盖约两个月。
- final holdout 交易数偏少时容易出现偶然正收益。
- 对开盘、收盘、波动 regime、事件日的拆分不足。

下一轮应采用分层数据窗口：

- discovery window: 快速发现是否有 gross edge。
- validation window: 多个月、多 regime。
- final holdout: 完全隐藏，LLM 不可读取。
- replay window: tick 或 conservative bar fill 验证可执行性。

### 3.5 成本不是唯一问题，但必须继续保守

当前 NQ conservative cost model 约为：

- 单边 1 tick 滑点。
- round-trip fees 5 美元。
- 每笔约 15 美元总成本。

第一轮加回成本后仍没有正 gross edge，所以不能靠降低成本“制造盈利”。后续策略必须先证明：

- pre-cost gross edge 为正。
- net-of-cost 后仍为正。
- 额外 1 tick 滑点后不崩溃。

## 4. 优化目标

下一阶段目标不应直接追求“立刻找到 Sharpe > 2 的策略”，而应分成三层：

### 4.1 搜索质量目标

- 每个 `feature_set` 必须能追踪到实际执行条件。
- 每个策略必须记录 feature lineage、signal grammar、参数空间、成本模型、数据版本。
- 每轮搜索必须产出 family-level 和 feature-level 归因报告。

### 4.2 候选发现目标

先寻找更弱但真实的候选：

- 年交易次数 `> 300`。
- test Sharpe `> 0.5`。
- pre-cost gross edge `> 2 * round_trip_cost`。
- 至少 3 个非重叠测试窗口有交易。
- 反向信号不是显著更好。

满足后再晋级强目标：

- 年交易次数 `> 1000`。
- net-of-cost Sharpe `> 1`。
- win probability `> 53%` 或 profit factor `> 1.2`。
- final holdout 不显著衰减。

最终目标仍保持：

- 年交易次数 `> 1000`。
- Sharpe `> 2`。
- win probability `> 53%`。
- profit factor `> 1.2`。
- 成本、滑点、参数稳定性、paper shadow 全部通过。

### 4.3 学习目标

作为交易新手，系统应优先帮助用户学习：

- 哪些特征没有边际。
- 哪些策略 family 在什么 regime 下失败。
- 哪些策略看似高胜率但尾部亏损不可接受。
- 哪些候选只是数据挖掘产物。
- 为什么某个策略不能进入 paper 或 live。

## 5. 架构优化方案

### 5.1 Feature Registry 升级

为每个特征增加结构化字段：

- `name`
- `category`
- `data_level`
- `implementation_status`
- `required_inputs`
- `lookback_bars`
- `warmup_bars`
- `session_scope`
- `leakage_risk`
- `execution_availability`
- `expected_effect`
- `known_failure_modes`

验收口径：

- 所有策略引用的特征必须能在 registry 中找到。
- `implementation_status != implemented` 的特征不能进入可回测策略。
- 高泄漏风险特征必须默认禁止进入策略生成。

### 5.2 Executable Feature Engine

新增统一特征计算层，将 feature registry 中的特征计算为 bar/tick columns：

- trend: EMA slope、MA spread、ADX proxy、higher-high/lower-low。
- momentum: multi-horizon returns、rate of change、breakout distance。
- mean reversion: z-score、Bollinger distance、VWAP distance。
- volatility: ATR、realized volatility、range percentile、compression/expansion。
- liquidity: spread、tick count、bar volume proxy。
- time/session: open phase、lunch phase、close phase、minutes since open。
- gap/overnight: prior close distance、overnight range、opening gap。

验收口径：

- 回测结果中保存 feature snapshot hash。
- 每笔交易保存触发时的核心特征值。
- 可以单独运行 feature readiness report。

### 5.3 Signal Grammar

把策略从硬编码 family 逻辑升级为可组合 grammar：

```json
{
  "entry": {
    "long": {
      "all": [
        {"feature": "vwap_dist", "op": "<", "value": -6},
        {"feature": "range_percentile_20", "op": ">", "value": 0.7},
        {"feature": "minutes_since_open", "op": ">", "value": 20}
      ]
    }
  },
  "filters": {
    "all": [
      {"feature": "spread_ticks", "op": "<=", "value": 2},
      {"feature": "event_blackout", "op": "==", "value": false}
    ]
  },
  "exit": {
    "stop": {"type": "atr_multiple", "feature": "atr_14", "multiple": 1.2},
    "take_profit": {"type": "atr_multiple", "feature": "atr_14", "multiple": 1.8},
    "time_stop": {"minutes": 18}
  }
}
```

验收口径：

- `feature_set` 不再只是 metadata，必须至少有一个 feature 被 grammar 引用。
- 每条入场 signal 都可以解释为 feature predicates。
- 回测 audit 中保存 predicate evaluation。

### 5.4 Strategy Mutation Engine

对每个 seed 自动生成受控 mutation：

- `inverse_signal`: long/short 方向反转。
- `filter_add`: 添加 regime/time/liquidity filter。
- `exit_rewrite`: 固定点数退出改为 volatility-scaled exit。
- `threshold_sweep`: 阈值局部搜索。
- `session_shift`: 开盘、午盘、收盘分段搜索。
- `cooldown_add`: 增加亏损后冷却、连续信号去重。
- `risk_cap_adjust`: 日交易次数和最大持仓时间收缩。

验收口径：

- 所有 mutation 保存 parent hash。
- 系统性亏损策略必须先测试 inverse mutation。
- mutation 不能扩大参数空间到不可验证规模。

### 5.5 Cheap Pre-Screen

在 rolling validation 前增加快速筛选：

- 单窗口 pre-cost gross edge。
- 成本覆盖倍数。
- 交易数下限。
- 单日集中度。
- side balance。
- entry reason 分布。
- inverse signal 对照。

推荐 hard reject：

- `pre_cost_avg_trade <= 0`
- `net_avg_trade <= -round_trip_cost`
- `top_1_day_pnl_share > 40%`
- `trade_count < 30`
- `inverse_signal_net_pnl > original_net_pnl`

验收口径：

- 被 pre-screen 拒绝的策略不进入完整 walk-forward。
- pre-screen 报告保存到实验目录。

### 5.6 Anti-Overfit Validation

保持并加强现有验证：

- rolling walk-forward。
- purged/embargoed split。
- final holdout 隔离。
- 非重叠 test fold。
- 参数稳定性热力图。
- cost stress。
- Deflated Sharpe 或等价多重试验惩罚。
- PBO proxy 或 CSCV proxy。

验收口径：

- 任何策略不能只因单个窗口表现好而晋级。
- LLM 不能读取 final holdout 后再继续修改同一候选。
- 每个 promoted candidate 必须有 frozen spec。

### 5.7 Result Attribution

新增失败归因维度：

- `no_trade`: session/data mismatch。
- `negative_gross_edge`: 未扣成本前已经亏。
- `cost_fragile`: 毛利为正但成本后亏。
- `wrong_direction`: inverse signal 显著更好。
- `bad_exit`: 入场方向尚可，退出导致亏损扩大。
- `overtrading`: 交易过密且 avg trade 过低。
- `regime_specific`: 只在某个 regime 有效。
- `holdout_decay`: final holdout 衰减。
- `parameter_fragile`: 参数邻域不稳定。

验收口径：

- 每个 rejected candidate 有机器可读 reason。
- family、feature、mutation 三个层级都有统计报告。

## 6. 下一轮搜索流程

- `discovery`: 2018-05-24 到 2018-07-26，用于快速迭代。
- `validation`: 多个月跨 regime，用于验证候选。
- `holdout`: 完全隐藏，不进入 LLM feedback。

验收口径：

- 每个窗口记录 data_version_hash。

### 阶段 C：策略 grammar 接入

新增 5 个可组合策略模板：

- VWAP reclaim / rejection。
- Trend pullback with volatility-scaled exit。
- Opening range failure reversal。
- Volatility compression breakout with spread gate。
- Time-of-day mean reversion with regime filter。

验收口径：

- 每个模板至少引用 3 个 executable features。
- 每个模板都有 inverse mutation。
- 每个模板参数组合默认小于 50。

### 阶段 D：预筛和反向验证

对每个候选先跑：

- original signal。
- inverse signal。
- zero-cost diagnostic。
- conservative-cost diagnostic。
- trade distribution diagnostic。

验收口径：

- 只有 pre-cost gross edge 为正的 original 或 inverse 进入完整验证。
- 发现 inverse 明显更好时，自动记录为新 seed。

### 阶段 E：完整 walk-forward

晋级候选执行：

- rolling validation。
- non-overlap test folds。
- final holdout。
- cost stress。
- parameter stability。

验收口径：

- 候选必须先达到弱目标，再尝试强目标。
- 弱目标不通过时不允许声称“接近盈利”。

## 7. LLM 使用方式优化

LLM 不应直接“猜策略”，而应执行受控研究角色：

- 根据失败归因提出 feature hypothesis。
- 从 feature registry 中选择已实现特征。
- 输出受 schema 限制的 signal grammar。
- 解释为什么该特征组合可能在某个 regime 有效。
- 读取 train/validation feedback，但不能读取 final holdout。
- 不能扩大参数空间绕过反过拟合门槛。

LLM prompt 必须包含：

- 当前失败统计。
- 被禁止重复尝试的 pattern。
- 可用 feature list。
- 成本模型。
- session 和执行约束。
- 输出 schema。

LLM 输出必须经过 deterministic validator：

- feature 是否已实现。
- predicate 是否可计算。
- 参数空间是否受控。
- 是否有止损、time stop、daily risk cap。
- 是否引用未来数据。

## 8. 风险边界

系统必须继续保持以下边界：

- 任何新策略先进入 backtest，不直接 paper。
- paper shadow 只观察，不真实下单。
- micro-live 需要单独审批，不由本文授权。
- 禁止马丁、亏损加倍、网格摊平。
- 禁止用降低成本、降低滑点假设来制造达标。
- 禁止 final holdout 结果反馈给同一轮策略生成。

## 9. 实施优先级

### P0：修正搜索空间

- 实现 executable feature engine。
- 让 `feature_set` 进入 signal grammar。
- 加入 inverse mutation。
- 加入 pre-cost gross edge pre-screen。

### P1：提高验证质量

- 扩展多窗口数据选择。
- 增加 purged/embargoed split 标识。
- 增加 Deflated Sharpe / PBO proxy。
- 增加 feature/family/mutation attribution report。

### P2：增强策略表达

- 实现 volatility-scaled exits。
- 实现 liquidity/spread gates。
- 实现 event/session gates。
- 实现 feature-conditioned exits。

### P3：闭环优化

- 将 paper shadow 结果回填 memory。
- 用失败归因指导下一轮 LLM prompt。
- 在 WebUI 中展示 family、feature、mutation 的失败热力图。

## 10. 验收标准

优化完成后，系统应能回答：

- 一个策略到底使用了哪些可执行特征？
- 每笔交易触发时这些特征值是多少？
- 该策略未扣成本前是否有正边际？
- 成本、滑点、spread 压力后是否仍有效？
- 反向信号是否更好？
- 收益是否来自少数交易或单日？
- 参数邻域是否稳定？
- 哪些 feature/family/mutation 在历史上反复失败？
- LLM 是否读过 final holdout？
- 该候选为什么能或不能进入 paper shadow？

## 11. 立即下一步

下一轮不应继续直接执行 `research discover-target` 大预算搜索。推荐先实施：

1. `feature engine`: 将 30 个核心特征计算为可回测列。
2. `signal grammar`: 让策略 entry/filter/exit 引用这些特征。
3. `inverse mutation`: 对所有系统性亏损候选生成反向版本。
4. `cheap pre-screen`: 拒绝无 gross edge 的候选。
5. `attribution report`: 记录 family、feature、mutation 层面的失败原因。

完成后再重新跑目标发现。否则继续搜索只会扩大同一类负边际候选的数量。

## 12. 落地实现状态

本方案已落地为以下代码路径：

- `src/tlm/features.py`: executable feature engine，支持 30+ 个核心日内特征、feature snapshot hash、feature value lookup。
- `src/tlm/backtest.py`: `signal_grammar` bar backtester，支持可执行特征 predicates、filters、ATR/points exit、每笔交易 feature/predicate audit。
- `src/tlm/mutations.py`: controlled mutation engine，已实现 `inverse_signal`，保存 parent hash 和 mutation id。
- `src/tlm/prescreen.py`: cheap pre-screen，覆盖 gross edge、cost coverage、top-day concentration、side/entry distribution、inverse comparison。
- `src/tlm/attribution.py`: search attribution report，按 family、feature、mutation、pre-screen reason、failure mode 汇总。
- `src/tlm/research.py`: research artifact 已写入 `pre_screen_report`；target discovery summary 已写入 `attribution_report`。

对应测试：

- `tests/test_features.py`
- `tests/test_strategy_backtest.py`
- `tests/test_mutations.py`
- `tests/test_prescreen.py`
- `tests/test_attribution.py`

验收结论：

- `feature_set` 可通过 `signal_grammar` 进入真实回测条件。
- 每笔 grammar 交易保存触发时的 feature values 和 predicate evaluation。
- 系统性亏损候选可以生成 inverse mutation 并保留 lineage。
- 完整 research result 包含 cheap pre-screen 信息。
- discovery summary 包含 family / feature / mutation / failure mode 归因。
