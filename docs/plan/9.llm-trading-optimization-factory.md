# LLM 交易策略优化工厂完整落地方案

> 协调说明：本文晚于 `docs/plan/1-8` 生成。涉及“特征挖掘 -> 策略生成 -> 回测验证 -> paper/sim/live 复盘优化”的闭环、验收口径和实施优先级时，以本文为准。本文不授权任何 LLM 直接实盘下单；所有 live 能力仍受 NT8、Risk Gateway、readiness gate 和人工审批约束。

## 1. 目标和边界

本系统的目标不是让 LLM 预测市场或直接操盘，而是建立一个高通量、可审计、强反过拟合的交易策略优化工厂：

```text
Feature Mining
  -> Strategy Factory
  -> Backtest Validation
  -> Anti-Overfit Promotion
  -> Paper Shadow
  -> Sim / Micro Live
  -> Replay Attribution
  -> Memory Backfill
  -> Next Feature / Strategy Generation
```

核心原则：

- LLM 负责研究、生成候选、解释结果、复盘归因和提出下一轮实验。
- Deterministic code 负责特征计算、回测、风控、晋级、执行和审计。
- 所有策略必须来自可验证的 `Strategy Spec`、`feature_set`、`module_id` 和版本化参数空间。
- 任何无法通过样本外、成本、滑点、稳定性和实盘漂移验证的策略，都不能进入自动化执行。
- 新手使用本系统时，默认目标是学习和研究，不是扩大杠杆或追逐高频收益。

## 2. 目标指标的正确解释

用户当前目标是寻找：

- 年交易次数 `> 1000`
- Sharpe `> 2`
- 盈利概率 `> 53%`

这些是候选筛选门槛，不是充分条件。必须增加以下约束：

- `net_of_costs`: 扣除手续费、bid/ask、滑点、成交失败假设后仍达标。
- `walk_forward_stability`: 多个滚动窗口中表现稳定，不能只靠少数年份。
- `final_holdout_pass`: 最终隐藏样本通过，且本轮 LLM 未读取过该结果。
- `parameter_stability`: 参数附近区域表现不能断崖式坍塌。
- `trade_distribution`: 盈利不能集中在极少数异常交易或单一事件窗口。
- `drawdown_control`: 最大回撤、连续亏损、日亏损、尾部亏损必须可承受。
- `execution_feasibility`: 频率、持仓时间和交易时段必须能被真实执行链路承接。

## 3. 阶段 1：特征挖掘和治理

### 3.1 Feature Registry

每个特征必须登记为结构化定义：

- `name`
- `category`
- `data_level`: `bar`、`tick`、`quote`、`calendar`、`external_bar`
- `description`
- `required_inputs`
- `lookback_bars`
- `warmup_days`
- `implementation_status`: `candidate`、`implemented`、`external_required`、`blocked`
- `leakage_risk`: `low`、`medium`、`high`
- `supported_timeframes`
- `source_notes`

### 3.2 特征筛选

特征不能因为“听起来合理”进入策略。最小筛选流程：

- 单特征前瞻收益 IC、方向命中率、分位数收益。
- 按 time-of-day、波动 regime、事件窗口拆分。
- 计算成本后边际价值，而不是只看裸收益。
- 删除泄漏特征、未来函数、不可实盘获得的字段。
- 标记高度相关特征，避免 LLM 重复组合同一信息。

### 3.3 当前落地口径

当前仓库已经具备：

- `src/tlm/feature_catalog.py`: 100+ 日内特征候选目录。
- `src/tlm/strategy_generation.py`: 基于特征目录生成可回测 seed strategy。
- `strategies/nq_generated_feature_combo_*.yaml`: 第一批随机组合特征策略。

下一步必须补齐：

- feature registry 元数据扩展。
- feature readiness report。
- feature -> strategy -> result 的追踪 ID。
- 特征表现记忆表。

## 4. 阶段 2：策略生成工厂

策略生成不允许是自由文本。LLM 或随机生成器只能输出受控结构：

- 已批准 `strategy_family`
- 明确 `market_hypothesis`
- 明确 `feature_set`
- 有界 `parameters`
- 硬止损、止盈、最大持仓时间
- 最大日交易次数、最大仓位、最大日亏损
- 禁止马丁、无限 DCA、亏损加倍
- 可重放的 `generation_id` 和 `feature_combo_hash`

推荐生成层级：

1. `seed`: 基础市场假设和 family。
2. `feature_combo`: 随机或 LLM 组合出的特征上下文。
3. `parameter_variant`: 有界参数网格展开。
4. `validated_candidate`: 通过 train/validation 的候选。
5. `freeze_confirmed`: 通过 test/final holdout 的冻结版本。

## 5. 阶段 3：回测和反过拟合验证

### 5.1 必须执行的验证

- rolling walk-forward。
- final holdout 隐藏隔离。
- tick replay 或至少 conservative bar fill。
- 成本、滑点、spread 压力测试。
- 参数稳定性热力图。
- 年份、月份、时段、事件窗口拆分。
- trade count、win rate、Sharpe、profit factor、expectancy、drawdown 一起看。

### 5.2 晋级门槛

候选策略必须同时满足：

- `annual_trades > 1000`
- `sharpe > 2`
- `win_probability > 0.53`
- `profit_factor > 1.2`
- `max_drawdown` 在账户风险预算内。
- 至少 3 个非重叠 test fold 有交易。
- final holdout 不低于 test 表现的保守衰减阈值。
- 参数附近区域仍可盈利。

### 5.3 拒绝条件

自动拒绝：

- 高参数复杂度但样本不足。
- 主要收益来自单日、单事件、单行情 regime。
- 成本提高 1-2 tick 后收益消失。
- 交易过密导致真实执行不可承接。
- 策略逻辑依赖未来数据或不可实盘获得字段。
- 胜率提高来自扩大尾部亏损。

## 6. 阶段 4：Paper Shadow 和实盘前复盘

通过回测的策略不能直接 live。必须进入 paper shadow：

- 运行冻结策略，不下真实单。
- 保存 market snapshot、signal、risk decision、hypothetical fill。
- 对比回测假设和实时 bid/ask、spread、slippage。
- 记录每个阻断原因：事件窗口、数据延迟、spread 超阈值、kill switch。
- 生成 daily replay report。

Paper shadow 晋级 sim/micro-live 的最小要求：

- 连续足够交易日无系统错误。
- 信号可重放。
- hypothetic fill 与回测假设漂移可接受。
- 没有不可解释的大额偏差。
- 人工复盘确认策略假设仍成立。

## 7. 阶段 5：实盘复盘和优化

实盘只允许从 `micro-live` 开始：

- 极小仓位。
- 人工审批或白名单 profile。
- broker-side bracket/OCO。
- kill switch 默认可用。
- 日亏损、连续亏损、滑点异常自动停用。
- 每笔交易绑定 `strategy_spec_hash`、`module_id`、`risk_decision_id`、`gateway_command_id`。

复盘归因必须回答：

- 信号是否按预期触发？
- 风控是否正确审批或拒绝？
- 成交是否符合回测假设？
- 滑点、spread、延迟是否吞掉 edge？
- 当前亏损来自策略失效、执行漂移、市场 regime 变化，还是偶然波动？

## 8. LLM 的正确职责

LLM 可以做：

- 挖掘特征候选。
- 总结失败实验原因。
- 组合 seed strategy。
- 提出参数区间和假设。
- 解释 leaderboard 和 drift report。
- 生成下一轮实验计划。

LLM 不可以做：

- 绕过 validator 输出任意代码。
- 读取 final holdout 后继续调参。
- 直接下 live order。
- 覆盖 deterministic risk gate。
- 将未经验证的聊天结论写入 live strategy。

## 9. 最小可上线能力清单

在声称“优化闭环 100% 落地”前，必须全部完成：

- Feature registry 有 100+ 特征，且每个特征有 readiness metadata。
- Strategy factory 能稳定生成可回测、可审计、有界参数的候选。
- Backtest pipeline 自动输出目标达成、失败原因和反过拟合报告。
- Leaderboard 可筛选年交易次数、Sharpe、胜率、profit factor、回撤、稳定性。
- Paper shadow 能从 freeze-confirmed strategy 生成可重放 intent。
- Risk Gateway 能 deterministic approve/reject，且所有拒绝可审计。
- Runtime replay 能把实盘或 paper 交易归因回特征、策略、参数、风控和执行。
- LLM memory 能吸收成功和失败案例，驱动下一轮生成。
- Live readiness gate 默认阻断，只有 paper/sim/micro-live 验收完成后才放行。

## 10. BD 落地拆解

本方案对应一个 epic 和以下阶段任务：

1. 写入权威优化方案和协调 README。
2. 扩展 feature registry 元数据和 readiness report。
3. 强化 strategy factory 的 `generation_id`、`feature_combo_hash` 和复杂度约束。
4. 建立 anti-overfit promotion report。
5. 将目标筛选指标固化为 CLI/report gate。
6. 建立 feature/strategy/result memory backfill。
7. 完善 paper shadow replay artifact。
8. 完善 risk gateway 状态机和 readiness gate。
9. 在 WebUI 展示策略历史、筛选、对比图和 drift report。

每个阶段完成后必须：

- 有 BD issue。
- 有代码或文档变更。
- 有测试或可执行校验。
- 有 git commit。
- 不自动 `git push`，除非用户明确要求。

## 11. 当前实施优先级

当前最应先落地的是研究可信度，而不是 live：

1. Feature registry governance。
2. Strategy generation auditability。
3. Anti-overfit report。
4. Target discovery gate。
5. Paper shadow replay。
6. Execution readiness。

如果这些没有完成，即使某个回测看起来达到 Sharpe > 2，也只能视为研究候选，不能视为可赚钱策略。
